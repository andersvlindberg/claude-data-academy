# Lab 62: GDPR for a marketing campaign

| Role | Level | Time | Tools | Cost |
|---|---|---|---|---|
| Business / MarTech | L2 | 2 h | Docs | Free |

**Goal:** Check a campaign's lawful basis, consent and data minimisation before launch.

## How this lab works
1. **Hub:** open this step in your study hub and take the lecture (*Lecture*), or skip it if you know the theory.
2. **Claude Code:** the lecture ends with a practice project. Claude sets it up for you (a fictional scenario and generated data) and you build it in a real tool.
3. **GitHub:** commit as you go and merge it into your fork. Then tick it off in the hub.

```bash
cd claude-data-academy        # your fork
git checkout -b lab-62
mkdir -p my-work/lab-62-gdpr-for-marketing && cd my-work/lab-62-gdpr-for-marketing
claude
```
Type `LAB 62`. This is a brief lab: the coach turns the milestones below into steps for your level, and you write the code.

## Milestones
1. Describe purpose, data and recipients
2. Choose the lawful basis per purpose
3. Check consent text, retention and opt-out
4. Decide whether a DPIA is needed

## Done when
- [ ] Each purpose has a lawful basis
- [ ] Retention defined

## Save it to your portfolio
```bash
git add .
git commit -m "lab 62: <what you built>"
git push -u origin lab-62
```
Open a pull request in your fork, read your own diff like a reviewer, merge it, and mark the lab *Done* in your hub. Add a short `README.md` in the lab folder: what you built, how to run it, what you learned.
