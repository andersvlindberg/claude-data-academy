# Module 18: Presentation design and data storytelling

The best analysis is wasted if nobody understands it in the meeting. This module makes slides and reports look designed and land their message, so the bridge role is visible.

## How to use this skill

Follow `ae-coach` for mode. In BUILD mode (making a deck or report) work like a design director:
1. **Storyline before slides:** audience, the one thing they must take away, the decision asked for.
2. **Functional draft:** right content, right order, one message per slide.
3. **Design intent:** pick a system (palette, type scale, grid, one motif) that fits the topic.
4. **Elevate** with the techniques in [references/slide-system.md](references/slide-system.md).
5. **Interrogate** with [references/review-checklist.md](references/review-checklist.md).
6. **Restraint pass:** remove one element per slide that is not earning its place.
7. **Render and look** at every slide as an image before delivering; fix overflow, overlap, contrast.

Show only the finished result unless the learner asks for the reasoning. Respect any given template, brand or course format.

In LEARN mode, teach the principles with before/after examples and let the learner restructure their own deck.

## Mastery ladder

| Level | Evidence |
|---|---|
| L1 | Explains action titles, one message per slide and why charts need a takeaway |
| L2 | Restructures a deck with the pyramid principle and rewrites titles as takeaways |
| L3 | Builds a visually consistent deck (palette, type scale, grid, motif) with clear data charts; presents in time |
| L4 | Adapts the same analysis for executives, operations and technical audiences; handles hard questions |

## Core knowledge

### Structure
- **Pyramid principle:** answer first, then the supporting arguments, then the evidence.
- **SCQA:** Situation → Complication → Question → Answer. A strong opening for any analysis.
- **Action titles:** the title states the takeaway. "Conversion fell 18% on mobile after the checkout release", not "Conversion".
- **One message per slide.** If a slide needs two titles, it is two slides.
- **Executive summary** up front for decision meetings; appendix for detail.
- **Evidence chain** for investigations: expectation → observation → hypothesis and test → evidence → conclusion and what is not shown.

### Data storytelling
1. Know the context: who, what decision, how they will consume it.
2. Choose the right visual (line for time, bar for comparison, table for lookup).
3. Remove clutter: borders, heavy gridlines, 3D, redundant labels, legends that could be direct labels.
4. Focus attention: grey for context, one accent colour for the point.
5. Think like a designer: alignment, white space, hierarchy.
6. Tell the story: beginning (context), middle (insight), end (recommendation and next step).

### Visual system
- **Palette:** one dominant neutral, one primary, one sharp accent (≤10% of the surface). Pick colours for the topic, not default blue.
- **Type:** at most two families; strong size contrast (title 36–44 pt, body 14–18 pt, captions 10–12 pt); left-align body text.
- **Grid and spacing:** consistent margins (≥0.5 inch), consistent gaps, everything aligned.
- **Motif:** one repeated element (numbered markers, icons in circles, a geometric shape) for recognition.
- **Hero moment:** one big number or striking chart per section.

### Delivery
- Rehearse with a timer: about 1.5–2 minutes per content slide.
- Learn the first and last sentence by heart; the middle follows the titles.
- Nervous presenter tactics: slower than feels natural, pause after each key number, look at one friendly face per section, keep notes in speaker notes not on slides.
- For questions: repeat the question, answer briefly, admit what you do not know and say how you would find out.

## Common misconceptions

- "More text means more thorough." It means less read.
- "Every chart needs a legend." Direct labels are clearer.
- "Design is decoration." Design is hierarchy and focus.
- "Centered text looks professional." Left-aligned body text reads faster.
