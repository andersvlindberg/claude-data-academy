# Group work playbook

## Week 0: kick-off (60 minutes)
1. Read the brief together. Write the goal in one sentence and the grading criteria as a checklist.
2. Agree roles: **project lead** (owns plan and deadlines), **content leads** per part, **editor/design owner** for the final deck or report, **timekeeper/notes**. Rotate if the course is long.
3. Set up: one shared folder, one board (Trello, GitHub Projects or a simple table), one chat channel, one meeting rhythm.
4. Write a mini charter (template in templates.md) and a RACI.

## The project lead's job
- Break the brief into tasks with owners and dates; nothing is "everyone's".
- Run short check-ins: what's done, what's next, what's blocking.
- Track risks (absence, unclear brief, technical blockers) and raise them early with the teacher.
- Protect quality: definition of done per deliverable, review before hand-in.
- Not doing all the work; making sure all the work gets done.

## Shared presentations (the common failure point)
1. **Storyline first:** agree the message and the slide-by-slide outline (one message per slide, action titles) before anyone designs slides.
2. **One template:** the design owner sets the template (colours, fonts, title position, footer) on day one. Everyone builds inside it.
3. **Ownership per slide:** each slide has one owner in the outline table.
4. **Content freeze** a day before delivery; then only the editor changes layout so the deck looks like one voice.
5. **Rehearse** with timing; everyone can answer questions on every part.
6. **Backup plan:** the presentation works without a live demo (screenshots, PDF export).

## Evidence-chain presentations (investigation projects)
Service, action, expected result → observation and chosen deviation → hypothesis and test → technical evidence → conclusion, consequence and what could not be determined. One clear piece of evidence beats ten screenshots.

## Retrospective after delivery
Start / stop / continue, one action each for the next project.
