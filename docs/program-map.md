# Program map

How the academy covers typical courses in data education. The five example programs below are based on common vocational (higher vocational education) data programs; course names are translated and generalised. Use the map to find the skills behind any course you take, or to see what a program does not cover so you can fill the gap yourself.

## Example program 1 · Customer data developer

| Course | Primary skills | Supporting skills | Bridge to the chain |
|---|---|---|---|
| Digital platform technology | `ae-web-tracking` | `ae-project-method`, `ae-git-devops`, `ae-apis` | Where data is born: the click, the request, the cookie, the event |
| Data-driven business processes and business development | `ae-business-strategy`, `ae-business-journeys` | `ae-customer-data-platforms`, `ae-governance-gdpr`, `ae-bi-metrics` | Purpose, business models, goals, KPIs, journeys, data sources and flows |
| Marketing technology and customer data | `ae-martech`, `ae-crm-automation`, `ae-customer-data-platforms` | `ae-business-journeys`, `ae-web-tracking`, `ae-governance-gdpr` | The systems that use customer data and the KPIs they are judged on |
| Data management and data design | `ae-modeling` | `ae-sql`, `ae-governance-gdpr`, `ae-dbt` | How data is structured so it can be trusted |
| Data technology stack | `ae-data-engineering`, `ae-warehouses` | `ae-dbt`, `ae-mcp-tooling` | The tools that move, store and transform data |
| APIs and integration technology | `ae-apis` | `ae-systems-processes`, `ae-data-engineering`, `ae-python` | How systems talk to each other |
| Object-oriented programming 1 and 2 | `ae-python` | `ae-git-devops`, `ae-apis` | Structured, tested, reusable code |
| GDPR and law | `ae-governance-gdpr` | `ae-web-tracking`, `ae-martech` | What you may do with data, and how to prove it |
| AI and machine learning for customer data | `ae-ai-ml` | `ae-statistics`, `ae-analytics`, `ae-mcp-tooling` | Prediction, segmentation, LLMs and agents on customer data |
| Project management and development processes | `ae-project-method` | `ae-git-devops`, `ae-presentation-design` | How a team delivers |
| Internship | `ae-career` | all | Applying the chain at a real company |
| Thesis: business case | `ae-business-journeys`, `ae-business-strategy` | `ae-analytics`, `ae-presentation-design` | The capstone becomes the business case |

## Where programs often fall short, and how the academy fills it

| Common gap | Filled by |
|---|---|
| The modern transformation layer (dbt, tests, CI) is missing or brief | `ae-dbt`, `ae-git-devops` |
| Tools are taught in isolation, not as one chain | `ae-foundations`, the capstone |
| Unclear metric definitions and KPI math | `ae-bi-metrics`, `ae-martech`, `ae-business-strategy` |
| Statistics without experiments, or experiments without statistics | `ae-statistics`, `ae-analytics` |
| GDPR as theory without implementation in the warehouse | `ae-governance-gdpr` |
| AI covered as concepts, not as safe, verified workflows | `ae-ai-ml`, `ae-mcp-tooling` |
| Little portfolio evidence for internships | the capstone, `ae-career` |
| Presentations and dashboards that look like templates | `ae-design`, `ae-presentation-design` |

## Academic integrity

When an exercise or question belongs to graded coursework, the coach switches to LEARN mode: it explains concepts, works parallel examples, reviews your own attempt and debugs errors you show it, but it does not write the answer you hand in. You must always be able to explain anything AI helped you with.
